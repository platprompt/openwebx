# 0.2.0: chrome and arrival

Status: accepted by the user on 2026-09-28. Target version `0.2.0`.

## Why

The 0.1.0 site chrome (fixed HUD, overlay loader with a numeric counter and
fill bar, side navigation rail, pointer-following dot/ring cursor, a corner
"Sound on / Sound off" toggle with a remembered preference) and parts of the
creative brief followed external reference material too closely. openwebx is
MIT and ships only its own work, so that material is removed and redesigned
from openwebx's own requirements. **Implementers work from this document and
openwebx's own code only, and do not consult external reference
implementations.**

## Goals

1. **Content first.** The article is readable the moment the HTML arrives. The
   3D world is an enhancement that joins when ready; it never gates reading.
2. **Chrome lives in the content or in the world**, never as a fixed viewport
   template laid over the page.
3. **No shared default look.** Each form is chosen per brief, with a reason.
4. **Nothing is lost:** keyboard, no-JS, reduced motion, mobile, SEO, the
   runtime probe and the Artifact/Canvas bundle keep working.

## Removed (must not appear in the kit, scaffold output or QA-passing sites)

- Fixed viewport HUD: `.ox-hud`, fixed `.ox-brand`, `.ox-readout`, `.ox-cue`.
- Overlay loader: `.ox-loader`, a progressbar with a numeric counter, a fill
  bar and a step line; `data-count`, `data-step`; zero-padded counters.
- Fixed side navigation: `.ox-nav` gauge/clock/progress/dots/index variants,
  `.ox-nav__meter`, `--ox-nav-clear-*` padding.
- Pointer-following cursor: `.ox-cursor` dot/ring/label/charge, `cursor: none`.
  The kit never hides or replaces the operating-system cursor.
- Corner sound toggle, `data-sound-label`, the literal labels "Sound on" /
  "Sound off", and any persisted sound preference (no `localStorage`).
- `brief.loader`, `brief.cursor`, and chrome keys `nav`, `loader`, `readout`,
  `cursor`, `hold`, `nav_labels`.

## New model: `brief.chrome`

```json
"chrome": {
  "contents": "list",
  "folio": "value-name",
  "values": ["07:00", "09:00", "…"],
  "arrival": "scene",
  "tags": "anchored",
  "sound": "offer",
  "sound_label": {"off": "ฟังลมบนสันดอย", "on": "พักเสียงไว้ก่อน"},
  "reasons": {"contents": "…", "folio": "…", "arrival": "…", "tags": "…", "sound": "…"}
}
```

| Key | Options | Meaning |
|---|---|---|
| `contents` | `list` · `sentence` · `none` | An in-flow table of contents inside chapter 0, after the hero copy: a real `<nav id="contents">` whose `<ol>` links to `#ch-N`. `sentence` renders the chapter links inline inside one authored sentence (`chrome.contents_lead`, e.g. "This guide walks through"). `none` only for single-chapter pieces. |
| `folio` | `name` · `number-name` · `value-name` · `none` | A running head at the top of each chapter section, in that section's own flow (`position: sticky` inside the section, so it travels with its chapter and is never fixed to the viewport). `number-name` = "3 / 8 · Name"; `value-name` = `values[i]` + name. The folio links to `#contents`. |
| `values` | one string per chapter (optional) | Authored per-chapter values (hours of a day, stages of a climb). Never invent factual numbers the content does not state. Required for `value-name`. |
| `arrival` | `veil` · `scene` · `hold-title` | How the page arrives. `veil`: hero HTML visible at once; the canvas fades in from the page colour when the scene is ready. `scene`: same, but the scene itself visualises load progress (the kit shows nothing). `hold-title`: the hero headline's words wait, then reveal as the scene becomes ready. There is never a counter, bar or overlay. |
| `tags` | `anchored` · `none` | Labels for scene targets are one small element placed beside the target's projected screen position (not the pointer). Touch: shown on tap, kept until a tap elsewhere, and announced through a visually hidden polite live region. |
| `sound` | `offer` · `none` | `offer`: an in-flow `<button aria-pressed="false">` in chapter 0 (after the contents) whose label is `sound_label.off` / `sound_label.on`, authored as a short phrase in the theme's voice. Sound starts off on every visit; nothing is persisted. |
| `reasons` | one line per key | Required by the director; copied into `brief.md`. |

Defaults when a key is omitted: `list`, `name`, `veil`, `anchored`, `offer`,
with `sound_label` falling back to a neutral phrase from the UI language table
(not "Sound on/off"). The scaffold rejects the removed keys with a `BriefError`
that says how to migrate (`nav_labels` → `values`, `nav` → `contents` +
`folio`, `loader` → `arrival`, `cursor`/`hold` → `tags`).

`brief.arrival_status` (optional): one sentence announced to screen readers
when the world is ready. Default from the UI language table.

## Page structure (scaffold output)

- No elements fixed to the viewport except the skip link (on focus) and the
  canvas/atmosphere layers.
- Chapter 0 contains, in order: eyebrow, hero heading, lede, verbatim content,
  then the contents nav, then the sound offer.
- Every chapter section starts with its folio (unless `folio: none`).
- `<main id="content" aria-busy="true">` until the runtime reports ready; one
  visually hidden `<p class="ox-status" role="status">` receives the ready
  sentence.
- A single `<div class="ox-tag" aria-hidden="true">` layer for anchored tags,
  plus the visually hidden live region used on touch.
- The no-JS and failsafe paths show the complete content with no canvas. If the
  runtime is not ready after the failsafe delay, the canvas is hidden and
  nothing in the content was ever hidden; a world that arrives later still
  fades in (`.ox-late` replaces `.ox-failsafe`, the text stays shown).

## Runtime API (0.2.0)

- `ctx.tags.set(text | null, anchor, { kind: 'target' | 'hint' })`: `anchor`
  is a `THREE.Vector3` or `THREE.Object3D`. The runtime projects it with the
  scene's `camera` every frame and keeps the tag inside the stage (hidden where it would cover text). One tag
  at a time; `null` clears it. Replaces `ctx.cursor` (removed).
- `ctx.sound.cue(name, { intensity, pitch })`: named cues `touch` (hover),
  `grip` (press), `let-go` (release), `turn` (chapter change), `pass` (fast
  travel), `tick`, `open`. Each cue is a small recipe (partials or a filtered
  noise band plus an envelope) rendered once into an `AudioBuffer` with an
  `OfflineAudioContext` and replayed; output passes one gain and a soft-clip
  `WaveShaperNode` limiter. `brief.sound.pitch` and optional
  `brief.sound.cues` tune the recipes. Muted calls cost nothing. Replaces
  `ctx.sound.play` (removed).
- Load progress: `scene.load(progress)` is unchanged. With `arrival: scene`
  the bus also emits `arrival:progress` (0..1) and `arrival:ready`.
- `chapters`: sets `aria-current="true"` on the contents link and
  `is-current` on the chapter; keeps `document.documentElement.dataset.chapter`
  and the bus `chapter` event. No meters, no nav muting, no nav clearance.
- Probe: unchanged shape; `RUNTIME_VERSION = '0.2.0'`.

## QA gate: originality lint

`qa.py` fails a site when its generated page, CSS or scripts contain any
removed identifier or pattern listed above, the literal labels "Sound on" /
"Sound off", a zero-padded percentage counter, a `cursor: none` rule, or an
element fixed to the viewport other than the skip link, canvas and atmosphere.
It also fails the typeface set Instrument Serif + Inter Tight + JetBrains Mono
used together (a known reference house style); any one of them alone is fine
when the theme calls for it.

## Workflow change: quick by default

`/openwebx:create <theme> <content>` runs without questions: the director
proposes, picks the recommended concept and writes the brief (`mode: auto`),
then build, critique and present run as before. The grilling rounds run only
when the user asks (`--ask`, "ask me", or `/openwebx:grill-me`).
